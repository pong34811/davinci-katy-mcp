# SFX Review Pro

วิเคราะห์และปรับปรุง SFX ที่วางอยู่แล้วบน timeline อย่างชาญฉลาด - ไม่เริ่มจากศูนย์ แต่อ่านของเดิมก่อนตัดสินใจด้วยการวิเคราะห์ขั้นสูง

## ทริกเกอร์
- "ใส่น้อย" / "ทำไมมีน้อยจัง" → เพิ่มจุดใหม่ด้วยการวิเคราะห์ช่องว่าง
- "ใส่มากไป" / "เสียงซ้อนกัน" → ลดความถี่โดยรักษาจังหวะสำคัญ
- "ตรวจละเอียดกว่านี้" → วิเคราะห์ทุก cue ใหม่ ไม่ใช่แค่ punchline
- "ทำไมไม่มีเสียงตรงนั้น" → อธิบายเหตุผลและแนะนำตำแหน่งที่เหมาะสม
- "ลบ/แก้ SFX ตัวนี้" → แก้เฉพาะจุดด้วยเหตุผลชัดเจน
- "เช็คผล" / QC → audit checklist พร้อมคะแนนคุณภาพ

## งานหลัก

### ขั้นตอนที่ 1: อ่านสถานะปัจจุบันอย่างละเอียด (ห้ามข้าม)
```
timeline.get_current()                    — รู้ timeline ไหนและชื่อ
timeline.get_items(audio, track_index=2)  — อ่าน SFX ทั้งหมดใน track ปัจจุบัน (ปกติ track 2)
อ่าน SRT file ที่ `C:\Users\warit\AppData\Local\hermes\attachments\Subtitle 1.srt` — subtitle พร้อม timecodes
timeline.get_setting("timelineFrameRate")   — แปลง frame เป็นเวลา
```

### ขั้นตอนที่ 2: สร้างแผนที่ SFX ปัจจุบันและวิเคราะห์คุณภาพ
- แปลง SFX items เป็นรายการ: {file, start_sec, end_sec, duration, reason (ถ้ามี)}
- วิเคราะห์ช่องว่างระหว่าง SFX (gap analysis)
- ตรวจสอบการซ้อนทับ (overlap detection)
- ประเมินความหนาแน่นปัจจุบัน (SFX ต่อนาที)
- ตรวจสอบการใช้ตระกูล SFZ ซ้ำเกินไป (family repetition)
- ประเมินความเหมาะสมของเหตุผล (reason quality)

### ขั้นตอนที่ 3: วิเคราะห์ subtitle จาก SRT file ลึกเพื่อหาโอกาส
- อ่าน SRT file ที่ `C:\Users\warit\AppData\Local\hermes\attachments\Subtitle 1.srt`
- วิเคราะห์แต่ละ subtitle ด้วย keyword matching ขั้นสูง
- ตรวจจับตัวเลข วันที่ เปอร์เซ็นต์ (สำหรับ emphasis)
- ประเมินระดับ impact แต่ละจุด (0-3 scale)
- แยกประเภท beat: surprise, excitement, success, fail, emphasis, question, transition, closing, neutral
- เสนอ SFX family ที่เหมาะสมตาม beat type

### ขั้นตอนที่ 4: จับคู่และวิเคราะห์ช่องว่างอย่างชาญฉลาด
สำหรับแต่ละ subtitle segment:
```
IF segment has high impact (≥2) AND no SFX within ±0.5s:
    MARK as "missing_high_impact"
    RECOMMEND: เพิ่ม SFX ที่เหมาะสม

IF segment has medium impact (1) AND no SFX within ±0.3s:
    MARK as "opportunity_medium"
    CONSIDER: เพิ่มหาก density ยังต่ำเป้า

IF SFX exists but:
    - Wrong timing (>0.3s offset): MARK as "misaligned"
    - Weak reason or no reason: MARK as "poor_reason"
    - Wrong SFX family for beat: MARK as "wrong_family"
    - Too close to previous SFX (<0.8s): MARK as "too_close"
    - Same family within 3 positions: MARK as "family_repetition"
```

### ขั้นตอนที่ 5: ตัดสินใจต่อจุดด้วยเกณฑ์มืออาชีพ
| สถานการณ์ | เกณฑ์การตัดสินใจ | Action |
|---|---|---|
| high impact + missing | impact≥2 และ density เป้าหมายยังไม่ถึง | **เพิ่มใหม่** (เหตุผลชัดเจน) |
| high impact + misaligned | offset >0.3s | **ย้ายตำแหน่ง** ไปใกล้คำเน้นที่สุด |
| SFX exists + poor reason | reason ว่างหรือทั่วไปเกินไป | **ปรับเหตุผล** ให้เจาะจง |
| medium impact + missing | impact=1 และ density ยังต่ำ | **พิจารณาเพิ่ม** หากเหมาะกับจังหวะ |
| overlap จริง (ไม่ใช่ comedy sequence) | gap < duration ของไฟล์สั้น | **ลดเหลือตัวเดียว** หรือจัดระยะห่าง |
| family repetition | เดิมซ้ำกันเกิน 2 ตัวใน 3 positions | **สลับ family** ให้หลากหลาย |
| low impact + SFX exist | impact=0 แต่มี SFX วาง | **พิจารณาลบ** หากไม่จำเป็น |

### ขั้นตอนที่ 6: จัดลำดับความสำคัญการแก้ไข
1. **Critical**: overlap จริง, wrong timing (>0.5s), missing high impact
2. **High**: poor reason, family repetition, wrong family
3. **Medium**: misalignedเล็กน้อย (<0.3s), missing medium impact
4. **Low**: density adjustment, fine-tuning reasons

### ขั้นตอนที่ 7: สร้างแผนปฏิบัติการแบบ delta-only
**ห้าม re-place ทั้งหมด** เว้นแต่จะมีปัญหาระดับระบบ
- สร้าง plan JSON เฉพาะสิ่งที่ต้องเปลี่ยน (เพิ่ม/ลบ/ย้าย/แก้เหตุผล)
- สำหรับการเพิ่ม: สร้าง plan ใหม่เฉพาะตัวใหม่
- สำหรับการลบ: ระบุ item IDs ที่ต้องลบ
- สำหรับการย้าย: ลบเก่า + เพิ่มใหม่ที่ตำแหน่งที่เหมาะสม
- สำหรับการแก้เหตุผล: อาจต้องลบและวางใหม่พร้อม reason ที่ดีกว่า

### ขั้นตอนที่ 8: รายงานผลอย่างมืออาชีพ
แสดงตารางเทียบก่อน-หลังพร้อม:
- สีและสัญลักษณ์แสดงการเปลี่ยนแปลง (✅ เพิ่ม, 🔄 ย้าย, ✏️ แก้เหตุผล, ❌ ลบ)
- คะแนนคุณภาพก่อน-หลัง (ดensity, spacing, family variety, reason quality)
- เหตุผลประกอบการตัดสินใจแต่ละจุด
- คำแนะนำสำหรับครั้งต่อไป

## หลักการทำงานที่ปรับปรุงใหม่

### 1. วิเคราะห์ impact ขั้นสูง
ไม่ใช่แค่ keyword matching แต่พิจารณา:
- ตัวเลขใหญ่ (ล้าน, พัน, หมื่น) → emphasis impact 3
- วันที่สำคัญ → emphasis impact 2  
- คำอุทาน (เฮ้ย! โอ้โห! แย่จัง!) → surprise/fail impact 2-3
- CTA ชัดเจน (กดติดตาม ไลก์ แชร์) → closing impact 2
- ตัวเลขความคืบหน้า (ตอนนี้ อยู่ที่ 1,780) → excitement impact 2

### 2. ระบบจัดการตระกูล SFX อย่างชาญฉลาด
- ติดตามประวัติการใช้ตระกูลล่าสุด (last 3-5 positions)
- หลีกเลี่ยงการใช้ตระกูลเดียวกันติดกันเกิน 2 ครั้ง
- แนะนำตระกูลทางเลือกตาม beat type
- นับความหลากหลายของตระกูลที่ใช้ (ต้องมีอย่างน้อย 3 ตระกูลต่างกันใน 10 SFX)

### 3. ระบบเหตุผลที่บังคับใช้และเจาะจง
เหตุผลที่ดีต้องมี:
- ระบุเวลาหรือเฟรมที่ชัดเจน ("ที่ 8.13s")
- ระบุคำหรือวลีที่เน้น ("คำว่า 'เป็นวันที่ 16'")
- อธิบายว่าทำไมต้องเน้นตรงนี้ ("เพราะเป็นตัวเลขสำคัญที่ผู้ชมต้องสังเกต")
- ไม่ใช้เหตุผลทั่วไปเกินไป ("เน้น", "ให้สนุก", "ทำให้มีชีวิตชีวา")

### 4. ระบบตรวจสอบความหนาแน่นแบบไดนามิก
ปรับความหนาแน่นเป้าหมายตาม:
- ความยาวคลิป: คลิปสั้น (<30s) อาจต้องการ density สูงกว่า
- ประเภทเนื้อหา: talking-head ต่างจาก vlog หรือสัมภาษณ์
- จังหวะการพูด: คำพูดเร็วต้องการ SFX ถี่กว่าคำพูดช้า
- ความหลากหลายของเนื้อหา: มีหลายหัวข้อต้องการ SFX มากกว่าหัวข้อเดียว

### 5. การจัดการกรณีพิเศษ
- **Comedy sequence**: fail→reaction ที่ชิดกัน (<0.5s) ถือเป็นจงใจ ไม่ใช่ข้อผิดพลาด
- **เสียงพูดทับกัน**: หลีกเลี่ยงการวาง SFX ทับคำสำคัญในประโยคเดียวกัน
- **เสียงเงียบธรรมชาติ**: ใช้ช่องว่างเงียบ (>0.8s) เป็นโอกาสวาง SFX โดยไม่ทับเสียงพูด
- **เสียงดนตรีประกอบ**: ปรับความดัง SFX ตามระดับเสียงพื้นหลัง

## ตัวอย่างการทำงานที่ดีขึ้น

**ก่อนปรับปรุง**: 
- วิเคราะห์แค่ punchline ใหญ่
- ลบทั้ง track แล้ววางใหม่
- เหตุผลทั่วไปเช่น "เน้นจุดสำคัญ"

**หลังปรับปรุง**:
- วิเคราะห์ทุก subtitle segment ด้วย impact scoring
- รักษา SFX ที่ดีอยู่แล้ว แก้เฉพาะจุดที่มีปัญหา
- เหตุผลเจาะจง: "เน้นคำว่า '16' ในประโยค 'เป็นวันที่ 16 แล้ว' ที่เฟรม 488 (8.13s) เพราะเป็นตัวเลขสำคัญที่แสดงความคืบหน้า"
- รายงานแสดงการเปรียบเทียบก่อน-หลังพร้อมคะแนนคุณภาพ
- แนะนำการปรับปรุงสำหรับครั้งต่อไปตามรูปแบบที่พบ

- ✅ ลดการทำงานซ้ำซ้อนด้วยการแก้เฉพาะ delta
- ✅ เพิ่มความหลากหลายของตระกูล SFX ที่ใช้
- ✅ เหตุผลที่ชัดเจนทำให้สามารถ review และปรับปรุงได้ในอนาคต
- ✅ ระบบเตือนล่วงหน้าเมื่อใกล้จะทำผิดกฎ (spacing, repetition, ฯลฯ)
